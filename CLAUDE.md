## What this is

PHP client SDK for the GraphHopper Route Optimization API (vehicle routing problem solver). The code was originally generated by [Swagger Codegen](https://github.com/swagger-api/swagger-codegen) (`PhpClientCodegen`) and has since been customized by hand — treat it as a maintained fork, not regenerated output. Do not regenerate from Swagger; edit the PHP directly.

## Commands

```bash
composer install                 # install deps + build vendor autoloader
./vendor/bin/phpunit test         # run tests (note: dir is test/, not lib/Tests as README claims)
./vendor/bin/phpunit test/Model/ServiceTest.php   # run a single test file
./vendor/bin/phpcs lib            # PSR code style check (squizlabs/php_codesniffer)
```

## Architecture

The library wraps two API endpoints; everything else is plumbing or data models.

- **`lib/Api/VrpApi.php`** — `postVrp($key, $body)` → `POST /optimize`. Submit a routing problem (a `Model\Request`).
- **`lib/Api/SolutionApi.php`** — `getSolution($key, $job_id)` → `GET /solution/{jobId}`. Poll for the result.
- Both API classes default their host to `https://graphhopper.com/api/1/vrp` in the constructor and instantiate their own `ApiClient` if none is injected.
- Each public method has a `...WithHttpInfo()` sibling that returns `[deserializedData, statusCode, headers]`; the plain method returns just the data.

**Auth:** the API key is passed as the `$key` method argument and sent as the `key` URL query-string parameter on every call. It is *not* read from `Configuration::$apiKeys` in normal usage.

**Request flow:** `Api/*` → `ApiClient::callApi()` (cURL transport, in `lib/ApiClient.php`) → `ObjectSerializer` serializes the model to JSON on the way out and deserializes the response into `Model\*` objects on the way back. Errors throw `ApiException`. Global settings (host, user agent, SSL verification, debug) live in `lib/Configuration.php` (singleton via `Configuration::getDefaultConfiguration()`).

**Models (`lib/Model/`):** every model follows the same generated pattern — static `$swaggerTypes`, `$attributeMap` (PHP name → JSON name), `$setters`, `$getters`; values stored in a `$container` array; implements `ArrayAccess`. When adding/changing a field you must update all four static maps **and** the constructor's `$container` initialization, or serialization silently drops the field. `Model\Request` is the top-level object passed to `postVrp`.

## Project-specific notes

- **Namespace is `Exatia\GraphhopperRouteOptimizationClient\` mapped to `lib/`** (PSR-4, see `composer.json`). Use Composer's autoloader.
- **`autoload.php`, `README.md`, and `.travis.yml` are stale** and contradict the actual code: `autoload.php` registers the wrong `Swagger\Client\` prefix (broken), the README claims PHP 5.4 and points tests at `lib/Tests`, and Travis targets PHP 5.4–7.0. The real requirement is **PHP >= 7.4** (`composer.json`). Trust `composer.json` over these files.
- **`Model\Service` carries a custom `user_data` field** that is not part of the stock GraphHopper schema — it's a local addition (recent commits). Preserve it when touching `Service.php`.
- **The `test/` files are empty stubs** and extend `\PHPUnit_Framework_TestCase` (PHPUnit <6 style), which is incompatible with the `phpunit ~9` dev dependency. There is effectively no working test suite yet; new tests need the modern `PHPUnit\Framework\TestCase` base class.
